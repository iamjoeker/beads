# Known-red cmd/bd tests under Dolt (bd-9jl, bd-nn6).
#
# THIS FILE WANTS TO BE EMPTY, AND WAS. The CI jobs `Test (cmd/bd under real
# Dolt N/4)` and `Test (cmd/bd init under real Dolt)` run ./cmd/bd with
# BEADS_TEST_ENV_RUN_DOLT=1, i.e. WITHOUT the BEADS_TEST_SKIP=dolt that
# scripts/ci/lib/test-env.sh normally adds. That surface had never been run by
# any CI job, so it rotted: bd-kbx fixed 25 failures on pristine main and this
# list held the 12 that survived. bd-2k4 drained all 12, and for a while the
# jobs gated the whole package with nothing excused.
#
# It holds one entry again because bd-nn6 widened the gate to a second backend
# and the first full run of it found one test red on pristine main. A gate
# that grows by one excused test and one bead is working; the alternative was
# to keep the backend dark, which is what bd-nn6 was filed about.
#
# This list applies to BOTH of the wrapper's passes (bd-nn6): the server one
# above and the embedded one that follows it, which runs the same package with
# BEADS_TEST_EMBEDDED_DOLT=1 instead. An entry therefore excuses a test in
# whichever backend it is red under, and in the other one too. That is
# deliberate -- a single list is what keeps the count of excused tests
# readable -- but it means an entry costs more coverage than its one line
# suggests, and the reason on it should say which backend it was measured in.
#
# Rules:
#   - Adding an entry is a regression. It needs a bead and a reason on the
#     line, and it re-opens a hole in a gate that is currently whole.
#   - Every entry must name a top-level test that still exists in ./cmd/bd;
#     `scripts/ci/cmd-bd-dolt-known-red.sh check` enforces that, so a rename or
#     deletion cannot leave a dead line here pretending to cover something.
#   - The main job also re-runs any entries in a non-gating step, so one that
#     has quietly started passing shows up in the log as ready to delete.
#
# Measuring this surface on a shared box: pin BEADS_TEST_BD_BINARY to a path
# outside /tmp/beads-*. A concurrent scripts/test.sh run deletes the prebuilt
# bd out from under yours, and every subprocess test after that fails with an
# empty CombinedOutput -- 17 bogus failures the first time it happened here.
#
#   BEADS_TEST_ENV_RUN_DOLT=1 BEADS_CMD_BD_REQUIRE_DOLT=1 \
#     BEADS_TEST_BD_BINARY=/somewhere/stable/bd ./scripts/test.sh ./cmd/bd
#
# and for the embedded backend, WITHOUT either of those two -- they abort each
# other, which is why the wrapper makes two passes rather than one:
#
#   BEADS_TEST_EMBEDDED_DOLT=1 \
#     BEADS_TEST_BD_BINARY=/somewhere/stable/bd ./scripts/test.sh ./cmd/bd
#
# Note that the CI jobs shard by test name, so they never run ./cmd/bd as one
# process. The commands above are the stricter check: they are the ones that
# catch order-dependence between tests that CI's shards happen to separate.
# Two of bd-2k4's twelve were only ever red that way.
#
# Format: one top-level Go test name per line. `#` starts a comment.

# bd-dw5: red under the EMBEDDED backend on pristine main, and only there --
# it is embedded-gated, so it self-skips in the server pass. Asserts the
# "pass an absolute or ~/-prefixed --repo path" wording, which create.go
# cannot reach for a target directory that does not exist: the earlier
# "--repo target %q does not exist" stat check refuses first. The behaviour is
# right in both branches; which message the caller should see is the open
# question. Found by bd-nn6's first full embedded run of ./cmd/bd.
TestEmbeddedCreateRepoRelativeUninitRefused
