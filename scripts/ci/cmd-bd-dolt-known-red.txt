# Known-red cmd/bd tests under a real Dolt server (bd-9jl).
#
# THIS FILE IS EMPTY, AND THAT IS THE POINT. The CI jobs `Test (cmd/bd under
# real Dolt N/4)` and `Test (cmd/bd init under real Dolt)` run ./cmd/bd with
# BEADS_TEST_ENV_RUN_DOLT=1, i.e. WITHOUT the BEADS_TEST_SKIP=dolt that
# scripts/ci/lib/test-env.sh normally adds. That surface had never been run by
# any CI job, so it rotted: bd-kbx fixed 25 failures on pristine main and this
# list held the 12 that survived. bd-2k4 drained all 12, so the jobs now gate
# the whole package with nothing excused.
#
# Rules:
#   - Adding an entry is a regression. It needs a bead and a reason on the
#     line, and it re-opens a hole in a gate that is currently whole.
#   - Every entry must name a top-level test that still exists in ./cmd/bd;
#     `scripts/ci/cmd-bd-dolt-known-red.sh check` enforces that, so a rename or
#     deletion cannot leave a dead line here pretending to cover something.
#   - The main job also re-runs any entries in a non-gating step, so one that
#     has quietly started passing shows up in the log as ready to delete.
#
# Measuring this surface on a shared box: pin BEADS_TEST_BD_BINARY to a path
# outside /tmp/beads-*. A concurrent scripts/test.sh run deletes the prebuilt
# bd out from under yours, and every subprocess test after that fails with an
# empty CombinedOutput -- 17 bogus failures the first time it happened here.
#
#   BEADS_TEST_ENV_RUN_DOLT=1 BEADS_CMD_BD_REQUIRE_DOLT=1 \
#     BEADS_TEST_BD_BINARY=/somewhere/stable/bd ./scripts/test.sh ./cmd/bd
#
# Note that the CI jobs shard by test name, so they never run ./cmd/bd as one
# process. The command above is the stricter check: it is the one that catches
# order-dependence between tests that CI's shards happen to separate. Two of
# bd-2k4's twelve were only ever red that way.
#
# Format: one top-level Go test name per line. `#` starts a comment.
