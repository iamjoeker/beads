# Known-red cmd/bd tests under a real Dolt server (bd-9jl).
#
# The CI jobs `Test (cmd/bd under real Dolt N/4)` and `Test (cmd/bd init under
# real Dolt)` run ./cmd/bd with BEADS_TEST_ENV_RUN_DOLT=1, i.e. WITHOUT the
# BEADS_TEST_SKIP=dolt that scripts/ci/lib/test-env.sh normally adds. That
# surface had never been run by any CI job, so it rotted: bd-kbx found and
# fixed 25 failures on pristine main. These entries are the residue. The jobs
# skip exactly these so they can gate on the other ~2500 tests. Draining this
# file is tracked as bd-2k4, which carries what is known about each group.
#
# Rules:
#   - Removing an entry, by fixing its test, is the intended direction. Adding
#     one is a regression and needs a bead and a reason on the line.
#   - Every entry must name a top-level test that still exists in ./cmd/bd;
#     `scripts/ci/cmd-bd-dolt-known-red.sh check` enforces that, so a rename or
#     deletion cannot leave a dead line here pretending to cover something.
#   - The main job also re-runs these in a non-gating step, so an entry that has
#     quietly started passing shows up in the log as ready to delete.
#
# Provenance: measured on origin/main plus bd-kbx's two commits (d271d673e),
# real Dolt container, `BEADS_TEST_ENV_RUN_DOLT=1 ./scripts/test.sh ./cmd/bd`
# with no -skip: 12 failures out of 5508 tests, and this file is those 12.
#
# Measuring this again on a shared box: pin BEADS_TEST_BD_BINARY to a path
# outside /tmp/beads-*. A concurrent scripts/test.sh run deletes the prebuilt
# bd out from under yours, and every subprocess test after that fails with an
# empty CombinedOutput -- 17 bogus failures the first time it happened here.
#
# Format: one top-level Go test name per line. `#` starts a comment.
